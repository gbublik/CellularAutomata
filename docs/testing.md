# Automation tests — what each one covers

Detail behind the test-suite line in CLAUDE.md's Build / run section. Read before adding, changing or deleting a test in `Source/CellularAutomata/Private/Tests/AutomataTests.cpp`.

Sixteen tests, chosen for the places where a bug is both likely and invisible. Three cover slice capture (`Slice.Orientation` — the asymmetric-figure guard against mirroring and transposition described under `Automata/Capture/`; `Slice.Raster` — nearest-wins independent of input order, exact N×N blocks under scaling, budget refusal leaving no half-result, and empty input failing honestly rather than emitting a 1×1 file; `Slice.Tile` — the mirrored tiling turning `[0 1 2 3]` into `[0 1 2 3 2 1]`, width `2W−2`, i.e. the column past the edge must be the *penultimate* one rather than a repeat of the edge, which would lay a double line along every seam — checked on a four-colour strip, since on a flat-coloured image a mirror looks correct even when it is not). Four cover the generators (`Generation.Determinism` — same seed, same set, and a *different* seed giving a different one, since a generator that ignores the seed passes the first check perfectly; `Generation.RandomBallParity` — the golden test that `GenerateRandom()`'s refactor didn't silently shift every previously saved seed; `Generation.LatticeNeighborUniformity` — that the neighbour counts the presets promise are the counts the geometry actually has; `Generation.ParityFilter` — that the parity filter **partitions** the set rather than cuts it, i.e. `Even ∪ Odd` equals the unfiltered result *as a set* and not as a count (several generators emit the same cell more than once — `RandomBall` reject-samples with collisions — so summing lengths would prove nothing), which is what catches the trap in `FCellEmitter::Emit()` where a parity rejection must return `true`, since `false` there means overflow and would truncate the whole generator at the first node of the wrong parity; plus the closure that makes the FCC mode a lattice at all — a grid seeded on even cells must stay even *forever* under `Edges`/`EdgesFarAxes`, with `Moore` included as the counter-check that must break it, or the assertion would be vacuous). The other four: `Grid.NegativeCoords` (chunk math on negative coordinates — the floor-division trap flagged under `Automata/Grid/`, and generation is centred on the origin so negative coordinates are the norm, plus the "a re-created chunk must not inherit stale ages" guarantee), `Rules.RuleStringRoundTrip` (`Parse → Format → Parse`, range compression, every one of the 14 neighbourhood tokens surviving print-then-parse back into itself (a gap in the token table would otherwise fall through to its `M` fallback silently), and twelve malformed strings that must each be rejected *whole* with a non-empty error — including `M2` and `E2`, rejected rather than coerced), `Compute.CpuGpuParity` and `Compute.GpuBatchParity` (differential tests — they need no known-good answer, only that two implementations agree: CPU against GPU, and one batched dispatch against N single steps, comparing live cells, ages **and** decay stages). The last two are the automated form of the manual check the batching work was verified with, and they carry `EAutomationTestFlags::NonNullRHI` plus their own `GMaxRHIFeatureLevel` check so they report "skipped" rather than fail under `-nullrhi`. `Rules.NeighborhoodShells` checks the shell model itself rather than the 14 values one by one: that each shell is exactly one `d²` class with no strays from the 5×5×5 cube it is scanned from (`(2,1,0)` at `d²=5` is the one waiting to leak in), that every value equals the union of its own shells (by set algebra, since `6+8` and `12+2` both give 14 and counting alone would not notice classes swapped), that every value stays under the 26-offset ceiling, that `Moore` still returns its original offsets in the original order, that the parity properties the face-less sets exist for still hold, and that reach is 2 exactly where far axes are present. Two cover the lattice: `Lattice.OrthogonalRoundTrip` — `WorldToGrid()` must be the *exact* inverse of `GridToWorld()` at any per-axis step including an unequal Z, which is precisely the hole that existed while four hand-written divisions by `CellSize` stood in place of an inverse mapping (see `docs/lattice-and-cell-shapes.md`), plus a point taken *inside* a cell rather than at its centre landing in that cell — what the DDA pick stands on — and `WorldBoundsToCellRange()` covering every cell whose centre is in the box, asserted as a **superset** because the range is deliberately conservative while a lost cell would be a hole in the cull box's edge; `Lattice.ElongatedDodecahedronFaces` — that the twelve offsets are the actual **faces of the Voronoi cell** under a 2× Z stretch (a face towards `V` exists exactly when the midpoint to `V` is nearer the origin than any other sublattice node), which pins down both the √2 threshold and the *absence* of a face towards `(0,0,±2)`, plus BCC closure (all three coordinates of one parity, tested with `&1` rather than `%2`, which yields −1 on negatives and would silently pass), the 26-offset shader ceiling, and reach 2 — the GPU batch halo is computed from it, and an understated one silently drops border cells. `Rendering.ColorRamp` sweeps all four colour spaces against both curves and asserts that a key stop returns the key itself within 1/255: that is the only thing that catches a broken there-and-back conversion, which otherwise shows up as a barely perceptible hue shift across the *whole* ramp and is indistinguishable from an intended colour. Alongside it: nothing outside `[0,1]` and no NaN (Catmull–Rom overshoots the key range by construction, and a NaN check must come first, since comparisons against NaN are all false), the degenerate inputs the settings panel relies on (an empty ramp is "material as-is", i.e. white; a single key gives itself at any `T`), and a guard that the middle of a red→blue ramp actually *differs* between LinearRgb and Oklab — without it an implementation that ignores the space setting entirely would pass everything else. Grey sits in the key set on purpose: it has no defined hue, and that is where a naive Oklch breaks (`atan2` of zero gives an arbitrary angle). The last, `GenerationHistory`, covers the sliding window behind the HUD graph (see `Ui/` below) — and it is the reason that logic was extracted out of the orchestrator into free functions at all: the traps in it (the last sample being edited *in place* rather than appended, the rendered value being carried forward, X mapped by generation value rather than by array index) are exactly the kind that need no actor, tick or render to exercise. The normalisation added on top of it is tested the same way and for the same reason: that `P(n)/n^d` really is flat on a set that grows as a clean power, that the fitted exponent comes out exactly 3 on `n³` and returns 0 rather than a NaN when there is nothing to fit, that generation 0 is dropped from *both* series at once (leaving them the same length) and takes the window's left edge with it, and that the axis segment never collapses to zero width — it is divided by. Note the whole run costs an editor startup (tens of seconds) — there is no fast inner loop for UE automation tests. Deliberately not covered: anything requiring an actor, a tick or a render — that is where UE tests get expensive and brittle, and it is checked by hand in PIE instead.
